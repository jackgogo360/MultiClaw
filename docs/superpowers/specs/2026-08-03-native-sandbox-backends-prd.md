# PRD: Native Sandbox Backends

Date: 2026-08-03
Status: approved for implementation planning
Source specification: `docs/superpowers/specs/2026-08-03-native-sandbox-backends-design.md`
Execution-gate mirror: `.omx/plans/prd-native-sandbox-backends.md`

## Problem

MultiClaw currently names an in-process timeout wrapper `ProcessSandbox`, while
`shell`, `code_exec`, and MCP stdio servers create host processes below that
wrapper. Approved commands can therefore access host files, network, environment,
and sockets without an OS isolation boundary.

## Outcome

All local process-launching capabilities execute through an OS-selected sandbox:

- macOS: `/usr/bin/sandbox-exec` with reviewed Seatbelt profiles
- Linux: nsjail with namespaces, mounts, seccomp, and rlimits

Backend absence, failed behavioral probes, invalid policy, or launch failure never
causes automatic host execution. The service remains live for diagnostics, reports
unhealthy readiness, and omits blocked risky capabilities.

## Users and jobs

### Operator

- Deploy MultiClaw without silently exposing host execution.
- See which backend/profile failed and which tools or MCP servers were skipped.
- Explicitly grant stdio MCP network, write, subprocess, runtime-root, or secret-env
  access per server.

### Agent user

- Keep existing shell quoting, pipes, redirects, cwd, timeout, output, and approval
  behavior when the sandbox is ready.
- Receive a clear unavailable/policy/launch/timeout error rather than misleading
  success or host fallback.

### Contributor

- Test policy rendering on either development OS without needing both backends.
- Run native negative tests on the matching macOS or Linux release environment.

## Functional requirements

### FR-1: Typed configuration

- Replace free-form `GovernanceSettings.sandbox_mode` with nested typed settings.
- Supported modes are `auto` and `host_unsafe_dev_only`.
- Legacy `process` maps to `auto` with a deprecation warning.
- Legacy `docker` is a hard configuration error.
- Legacy and nested sandbox configuration cannot be combined in one effective config.
- `host_unsafe_dev_only` requires `app.debug=true` and never activates implicitly.
- The debug requirement cannot be disabled; an unprobed `auto` backend remains blocked.

### FR-2: Common execution contract

- Support mutually exclusive `shell_string` and `exec_argv` requests.
- Validate canonical cwd, exact entrypoint, environment grants, filesystem roots,
  network mode, and profile readiness before rendering a launch.
- One-shot runner owns process groups, stdin, stdout/stderr bytes, timeout, TERM,
  KILL, and descendant cleanup; the manager owns private-root cleanup.
- MCP stdio consumes a rendered wrapper through the installed MCP SDK rather than
  reimplementing JSON-RPC transport.

### FR-3: Environment and path policy

- Create per-launch private `TMPDIR` and empty private `HOME`.
- Private launch-directory names are generated by the runtime and never derived from correlation IDs.
- Remove one-shot private roots after completion/failure, remove stdio roots after
  disconnect, and verify no residual roots at application shutdown.
- Use a strict baseline environment, synthetic USER/LOGNAME, and redirected XDG directories.
- Runtime-owned HOME/TMPDIR/PATH/identity/XDG keys cannot be overridden, even by an env allowlist.
- Keep `.git` readable but write-protected.
- Hide `.env` and `.env.*` from process read views when the profile requires it.
- Reject secret-shaped environment overrides unless the MCP server explicitly
  lists the exact key in `sandbox_env_allowlist`.
- Allow stdio MCP to declare canonical `sandbox_read_only_paths` for external
  runtimes such as Node or Python installations; each grant is logged and the
  common contract permits at most 16 explicit roots per launch.
- Build MCP PATH only from the platform baseline and explicitly granted runtime `bin` directories.

### FR-4: Platform backends

- Seatbelt uses static application-owned SBPL templates and `-D` path parameters.
- nsjail uses application-owned protobuf-text templates and serialized dynamic data.
- Runtime behavioral probes test allowed execution, denied outside-workspace write,
  denied default network, protected paths, and code-exec child-process denial.
- Unsupported OS is equivalent to unavailable backend in `auto`.

### FR-5: Readiness and registration gating

- Create one immutable `SandboxReadiness` snapshot during agent construction.
- Gate `shell` and `code_exec` before registry insertion.
- Gate stdio and in-process MCP before `connect_servers()`.
- Remote HTTP/SSE/WebSocket MCP remains available and is marked as outside the
  local OS sandbox boundary.
- Store readiness on `app.state.sandbox_readiness` and expose public
  `GET /health/ready` with HTTP 200 when ready and HTTP 503 when blocked.

### FR-6: Shell compatibility

- Preserve raw command-string semantics using an exec-form wrapper whose target is
  exactly `/bin/sh -c <command>`.
- Preserve cwd validation, existing safety checks, output formatting/truncation,
  real exit code, stderr labeling, timeout marker, and process-group cleanup.

### FR-7: Code execution migration

- Remove `multiprocessing.Manager()` and `multiprocessing.Process()`.
- Launch one exact Python interpreter with code supplied through stdin.
- Keep `restrict_builtins=True` as the default defense-in-depth policy.
- Use a JSON envelope to preserve current stdout/stderr/error/result semantics.
- Missing/malformed/oversized envelopes are internal errors, never success.

### FR-8: MCP transport policy

- Extend stdio config with `cwd`, `sandbox_network`, `sandbox_workspace`,
  `sandbox_allow_subprocesses`, `sandbox_env_allowlist`, and
  `sandbox_read_only_paths`.
- Defaults are network disabled, workspace read-only, subprocesses disabled, no
  secret env grants, and no extra runtime roots.
- In-process transport is rejected in `auto` and accepted only in unsafe dev mode.
- Stdio connect/disconnect/reconnect and dynamic tool refresh remain functional.

### FR-9: Observability

- Emit `sandbox.probed`, `sandbox.profile_unavailable`,
  `sandbox.registration_skipped`, `sandbox.launch_failed`, and
  `sandbox.unsafe_fallback_used` events.
- Structured logs include tool/transport/backend/profile/mode/correlation/server.
- Existing audit schema remains unchanged; sandbox context is encoded in `detail`.
- User-visible errors and readiness responses never expose secret values.

## Non-functional requirements

- No new Python package dependencies.
- Linux nsjail is an external deployment prerequisite.
- Policy rendering never invokes a shell or interpolates raw user values into
  Seatbelt/nsjail policy text.
- Existing scheduler approval and event ordering remains stable.
- Normal unit tests run without requiring a native backend; native negative tests
  are explicitly marked and platform-gated.
- All changes remain reversible by configuration/commit without data migration.

## Delivery slices

1. Typed settings, execution-guard rename, models, environment policy.
2. Process runner and fake backend contract.
3. Seatbelt backend and macOS behavioral probe.
4. nsjail backend and Linux behavioral probe.
5. Manager, readiness, server gating, health route.
6. Shell integration.
7. Code-exec single-interpreter runner.
8. MCP transport policy and lifecycle integration.
9. Observability, documentation, native release verification.

Each slice must pass its focused tests and be committed independently. The default
configuration changes to effective `auto` only after slices 1-8 and both native
negative suites are green.

## Acceptance criteria

1. `auto` selects Seatbelt on Darwin and nsjail on Linux; other OS values fail closed.
2. A missing or failed backend yields readiness 503, omits `shell`/`code_exec`, skips
   stdio MCP, and never launches a host child.
3. Unsafe host execution is impossible unless mode is explicit and debug is true;
   startup and every unsafe launch emit high-severity evidence.
4. Shell compatibility tests cover quoting, pipes, redirects, globbing, env assignment,
   cwd, stdout/stderr, exit code, timeout, and orphan cleanup.
5. Code-exec preserves success, exception, timeout, and truncation contracts with one
   interpreter child and no multiprocessing helper.
6. Default shell/code-exec network and outside-workspace writes are denied on both OSes.
7. `.git` writes and `.env*` reads are denied according to policy on both OSes.
8. Stdio MCP honors its explicit grants; in-process and remote transports follow the
   transport matrix.
9. Approval/audit/tool events retain current ordering for registered tools.
10. Relevant unit/integration suite, full backend suite, and platform-native release
    checks pass with no secret-bearing logs or responses.

## Rollback

- Revert the sandbox implementation commits and restore the previous config schema.
- Do not introduce a production `off` rollback switch.
- During staged rollout, rollback is commit/config deployment rollback; unsafe dev mode
  is not an operational production fallback.
